# Data Knowledge Instructions

In addition to parent instructions, distinguish:

- transactional workloads, consistency, concurrency, and integrity;
- analytical workloads, historical modeling, and query shape;
- streaming semantics, time, ordering, replay, and delivery;
- governance, ownership, lineage, quality, retention, residency, and deletion.

Do not treat these as interchangeable uses of “data architecture.” State the
data owner, system of record, schema authority, consistency boundary, retention
and privacy assumptions, failure recovery, migration path, and workload shape.
Separate logical guarantees from database or platform product behavior.
