# Security Knowledge Instructions

In addition to parent instructions:

- Prefer current standards, protocol specifications, official government or
  recognized security-authority guidance, and original threat research.
- Never invent cryptographic algorithms or protocol variations.
- State threat actors, protected assets, trust boundaries, attack surfaces,
  assumed capabilities, and residual risk.
- Separate authentication, authorization, identity proofing, session, key, and
  audit concerns.
- Distinguish protocol properties from product implementations and deployment
  profiles.
- Record version, profile, and known deprecation or supersession status.
- A security control must state the threats it mitigates, conditions, bypass or
  failure modes, verification, and operational burden.
- Vendor or community material alone is insufficient for security-critical
  normative claims.
