# ADR 0008 — Decision Guide Validation Kernel

Status: proposed implementation decision Date: 2026-09-02

This record is machine-authored. It is not human-reviewed, approved, published, or canonical. It
does not change any knowledge lifecycle state.

## Context

M7.0 separated reusable decision guides from project sessions, recommendations, and draft decision
artifacts. The original guide schema did not enforce complete comparisons, claim applicability,
evidence grounding, privacy, uncertainty, or human authority. Graph and retrieval contracts also
treated only concepts, claims, sources, and relationships as first-class.

Ansha Cerbia explicitly approved completion of M7.0 and authorized the bounded M7.1 kernel on
2026-09-02. That authorization was required by the M7.0 entry decision and scope-control handoff,
not by a general governance rule requiring human approval for ordinary code changes. Repository
governance requires explicit human authority when crossing human-only lifecycle transitions; M7.1
crosses none and all content remains `proposed`.

## Decision

Adopt four separate closed contracts:

1. `decision-guide` v2 is reusable governed knowledge identified by `AKG`.
2. A decision session is ephemeral context, has no governed record kind, and cannot approve a
   decision.
3. A recommendation is a contextual, evidence-bearing result that repeats its applicable context and
   constraint outcomes; it is never a decision.
4. An ADR/RFC/PAD artifact contract can represent only a draft and requires human acceptance outside
   automation.

Guide validation is fail closed. It requires:

- typed context variables and explicit sensitivity;
- declared constraint, assumption, quality-attribute, option, and criterion references with
  compatible concept types;
- exactly one trade-off cell for every option/criterion pair, including explicit `not-applicable`
  assessments rather than silent omission;
- an exact evidence inventory with no unbound or undeclared claims;
- sourced claims transitively grounded in admitted sources;
- claim applicability to every concept assessed by a binding;
- preservation of claim conditions at each binding;
- explicit uncertainty behavior, ephemeral session persistence, and external provider authorization
  policy with scoped authorization evidence; and
- immutable authority constants: recommendation-only, human decision required, automation cannot
  approve, generated artifacts remain drafts.

Decision guides become a first-class graph node and index family. Versioned provenance edges connect
guides to evidence claims, options, constraints, and quality attributes. Retrieval creates cited
guide overview and semantic-section units. These features support future runtime work without
implementing it.

## Contract migrations

- schema registry version: 3 to 4;
- decision-guide schema version: 1 to 2;
- graph and graph-generator contracts: 1 to 2;
- retrieval, unit, and generator contracts: 1 to 2;
- PostgreSQL retrieval unit constraint extended by migration `0002_decision_guide_retrieval.sql`.

No decision-guide instances existed, so the schema migration has no content rewrite. Generated
graph, retrieval, and integrity artifacts are regenerated by their committed generators only.

## Rejected alternatives

- Reusing one schema for guides, sessions, recommendations, and artifacts would blur lifecycle,
  persistence, and authority semantics.
- Optional matrix cells would make missing analysis indistinguishable from a deliberate
  not-applicable result.
- Universal numeric weighting would imply false precision across incompatible units and contexts.
- Treating guides as generic opaque graph records would prevent explicit provenance and
  retrieval-currentness checks.
- Persisting sessions by default would introduce privacy and retention behavior before it is
  authorized or operationally designed.

## Consequences and unresolved decisions

The kernel is stricter and authoring a guide will require more evidence work. That cost is
intentional because recommendations are expensive to correct after use. Remaining decisions include
whether active guides need `human_key`, whether redacted session snapshots ever become governed
records, and which later evaluation corpus is representative. None blocks this validation kernel;
all block silent expansion into corpus or runtime work.
